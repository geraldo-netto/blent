## Publication and native boundaries

The original FIFO descriptor, namespace directory and lease cookie remain owned
by the existing retained worker/lease lifecycle. Valid sparse records are only
500 or 1000 ms, private, bounded and short-lived. The C reader was admitted before
first source access and rejects preexisting advice for its entire lifetime;
current Rust atomic publication is independently accepted on that original fd.
The native writer rechecks advice within 200 ms and wakes for actual fresh
frames, cursor/stop and its existing synchronization conditions.

Filesystem publication may wait. After acquiring the native directory lock,
and again after staging writes immediately before rename, publication ticks the
same owned policy with the current proof clock and rechecks original live
observations. Loss or expired receipt proof cannot renew stale advice at those
boundaries. Failed staging admission retires its temporary file under the
original guard and preserves the previous committed record. These are advisory
observation points: there is no atomic transaction with later media revocation,
and no promise that a stalled filesystem or scheduler meets a wall-clock
revocation deadline. Subsequent loss wakes clear; native expiry/rechecks remain
separate controls. Advice never grants media access, source replacement or
native resource release.
