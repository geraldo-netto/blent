## Ownership and boundary review

EVDI capture owns registered backing storage and mode transitions. Mode dimensions
bound aligned stride/allocation arithmetic before conversion. The writer borrows
immutable frame leases; conversion completion, writer lease retirement and final
join precede storage release. A retirement timeout retains old allocations rather
than authorizing reuse. Final capture teardown unregisters native buffers before
freeing them. The previous T1284 issue remains corrected.

FIFO state belongs to the writer. Partial writes quarantine the original FIFO
identity with a retained descriptor; a replacement reader does not make old queued
bytes valid. Capture-control acknowledgements follow completed transitions.
Shared-ring mapping/descriptor ownership is separate in each process; slot atomics
and generation/nonce records govern publication and reuse. Socket backpressure
retains the relevant state or stops the helper; it does not certify a reader fence.

The conversion pool owns its workers and job storage. Borrowed source/output views
survive every active job and are released after completion/join. Cursor image
adoption and copied-image paths retain one authoritative allocation owner. Damage
and byte-order bounds were checked at their current callers.

The USB helper retains target identity/port ownership through its native operation.
Stream worker stack arguments live until the helper exits; fatal paths end the
isolated process instead of closing handles beneath a continuing worker. This
process-exit design must not be converted mechanically into a Rust library return.

GPU capture keeps the RGB lease through X synchronization and VPP completion;
encoder-owned NV12 frames survive codec references. Cursor shape refresh retires
old Pictures before replacing cached metadata. Failure to destroy a per-frame VA
parameter buffer terminates the helper (T1283), avoiding continued accumulation.
VA/X/libusb/driver cleanup semantics still require native evidence; Rust Drop or a
reference count would not prove them. Eventual cleanup assumes the relevant native
operations terminate or the owning process is actually retired.

Benchmark review covered argument bounds, paired worker completion, memory bounds,
file descriptors, temporary mappings and assertion build guards. Revision-specific
comparison harnesses intentionally compile pinned historical implementations;
`c-review-performance.py` pins its private ABI to `a3c053e`. Their historical
adapters are experimental controls, not shipped compatibility paths.

## Proposed Rust migration — T1401

Recommend a staged capture-helper migration if the owner chooses to fund it.
The concrete benefit is expressing allocation ownership, borrowed frame lifetimes
and validated control states in types within the existing Rust workspace. The
current C helper already has substantial explicit guards; the review does not
justify an urgent wholesale rewrite or claim a measured performance gain.

1. First outcome: a separate Rust capture-helper process with an independent
   control contract and a narrow Linux libevdi adapter. Reuse
   `common/src/capture_activity.rs` rather than introducing a second Rust codec.
   Keep callback context addresses stable, reject unwinding across C callbacks,
   and retain original registered storage until native unregister/quiescence.
2. Dependent outcome: replace the frame-exchange/writer owner with scoped frame
   leases and explicit generation transitions. Stop admission, retain uncertain
   native work, join the original workers, then free/reuse buffers. Keep one state
   owner; do not add a parallel compatibility implementation.
3. Integration acceptance: resume the permanent invalid-input, allocation-failure,
   partial-write, cancellation, resize and retirement regressions; measure each
   maintained function's coverage and complexity; then compare representative
   end-to-end latency, CPU, retained/peak memory and shutdown costs. Native display
   acceptance also requires T1389. Remove replaced C paths after acceptance.

Keep the SIMD converter in C initially behind a narrow borrowed-slice boundary.
Its Rust replacement requires measured value. Keep GPU and libusb adapters scoped
separately: their central risks are native identity, asynchronous access and exit
settlement, which a language change does not remove. No migration was implemented.
The single pending decision is recorded under Display capture and routing in
`TODO.md`; implementation outcomes must receive distinct IDs if selected.

Rust's official [FFI guidance](https://doc.rust-lang.org/nomicon/ffi.html) requires
correct declarations and manual foreign-pointer/thread-safety contracts. The
[Pin contract](https://doc.rust-lang.org/std/pin/index.html) supplies address
stability under its rules, not native callback retirement. Dropping a
[JoinHandle](https://doc.rust-lang.org/std/thread/struct.JoinHandle.html) detaches
its thread; explicit completion ownership remains necessary. The proposal applies
these documented constraints to Blent's source architecture; its expected
maintainability benefit is an engineering assessment, not a benchmark result.
