# Hosted tunnel write handoffs — 2026-11-22

## T1755: measured baseline and bounded candidate

The production ConnectionFrameWriter and StreamConnectionIo run over private
loopback TLS 1.3 with TLS_AES_256_GCM_SHA384. A benchmark-only candidate gathers
header/body and flushes on the writing worker. The current 64-KiB request limit
remains, so full payloads require two candidate writes. No production transport,
worker IPC, installed app, saved peer or tablet was changed.

There are 64 completed trials: 16 warmups and 48 measured trials. Each sends 60
frames, giving three alternating pairs for each of four payload sizes at burst
rate and 60 fps. Every peer header and payload byte is checked; every native
completion must name the original request. Only one frame is outstanding before
its acknowledgement. This measures a hosted driver/worker round trip, not the
full session reactor, Android IPC, display latency or pipelined throughput.

| Payload | TLS records/frame, baseline → candidate | Native completions/frame including ACK | 60-fps paired CPU ratio | 60-fps paired p95 ratio |
| --- | --- | --- | --- | --- |
| 64 bytes | 2 → 1 | 4 → 2 | 0.724 | 0.711 |
| 4 KiB | 2 → 1 | 4 → 2 | 0.974 | 0.881 |
| 16 KiB | 3 → 2 | 4 → 2 | 0.831 | 0.848 |
| 64 KiB | 6 → 6 | 4 → 3 | 0.994 | 1.128 |

Ratios are medians of three matched candidate/baseline pairs. CPU covers the
hosted driver and three native workers, excluding peer validation. These are
local point estimates without statistical confidence or physical Android evidence.
In burst trials the small-frame CPU ratios are 0.60–0.65; 64 KiB remains near 0.97.
Driver poll/wait calls and observed ready hints are separate raw counters, not
kernel wakeups. The candidate retains 65,576 additional staging bytes per trial
and copies each payload; the production baseline reuses its writer across frames.

The evidence supports separating handoff reduction from copying policy. T1759
will establish one exact native write/flush transaction across current adapters;
T1760 will evaluate small-frame gathering without assuming full-payload copying
helps. The 64-KiB candidate's 60-fps p95 worsened about 13%, so it is not a default
recommendation. T1525 retains native CPU/end-to-end acceptance and read/local-flush
work; T1527 retains broader allocation measurement.

## Ownership, regressions and reproducibility

Each trial owns one private listener, original sockets, three I/O workers and one
peer thread. Cleanup closes original admission/streams, releases the peer's final
observation wait, joins exact workers and requires StreamConnectionIo.retired().
Failed construction closes every admitted resource before unwinding. The layered
socket closes both delegated and inherited Socket state. A deliberate omission of
the base close fails the permanent descriptor-identity test with one retained
socket; the failed test's JVM exit contains that control. The restored close passes.
No deadline is treated as proof of native retirement.

The TLS observer retains only a five-byte header and remaining-length counter;
it does not retain encrypted payloads. Five permanent hosted tests cover record
fragmentation, bounds, invalid extents, rejected writes and native descriptor
identity. Their normal Python tool fixture passes. Both existing idle-benchmark
registration/compilation tests also pass after sharing the authoritative hosted
NativeCounters adapter. Benchmark-only source sets and dependencies remain opt-in.

The runner preserves source hashes, JVM/platform identity, cipher/protocol, every
raw sample, monotonic trial progress and an atomic results file. Source inputs
were unchanged through the qualified run. The finite trial domain is not an
elapsed-time kill budget; five-second socket deadlines govern private setup/read
protocols. The repository checker measures 170 Kotlin/Python functions, maximum
complexity 7; Groovy compiler AST measures six maintained DSL closures, maximum 2.
Benchmarks are exempt from production line-coverage requirements; no production
function was changed by this measurement item.

Evidence: `artifacts/2026-11-22-tunnel/t1755-*`. The source and reproduction commands
are in `scripts/benchmarks/android-tunnel/README.md`. The analysis script was added
after the qualified measurements and has a separate recorded hash; it did not
participate in the measured execution.

## T1759: one native write/flush transaction

T1759 introduced `WriteFlushed` with at most two borrowed slices:
the remaining header and original payload. `StreamConnectionIo` writes both and
flushes on its original output worker, publishing one exact completion only after
flush returns. Data frames therefore use one output admission/completion instead
of three; metadata frames use one instead of two. T1759 added no payload staging
or copy; T1760 below adds an explicit bounded gathering policy.
The 64-KiB wire payload limit is unchanged; the native transaction permits at most
40 + 65,536 bytes, and each slice is independently checked before admission.

The independent transaction contract defines a short successful result as an exact
written prefix without final flush. The writer retains the same frame, offsets and
absolute deadline through such progress. A full successful result includes flush;
only then does the session receive the original frame and release its credit.
The native OutputStream adapter completes the full transaction or reports failure;
it never retries a failed transaction. Existing fragmented fixtures retain their
short-write, zero-progress, stale-receipt and deadline oracles under this contract.

The serialized runner owns frame admission, the reusable 40-byte header and the
caller's payload borrow. The native slot owns the exact request through execution
and unconsumed completion. Cancellation cuts off new admission and credit release;
it does not permit buffer reuse or claim worker exit. Errors leave the connection
on its original close/retirement path. Actual exit of read, write and close workers
(or containing-process settlement) remains the reuse fence. One occupied output
slot bounds the transaction to two slice descriptors plus the existing arrays;
there is no new queue, thread, retained payload copy or ownership cycle. Eventual
cleanup remains conditional on original native completion/close or process death.

The worker's IPC schema carries controls only. `SocketConnectionSetup.io` constructs
StreamConnectionIo inside the worker process, and AndroidConnectionWorker composes
its session runner there. No frame/request crosses ConnectionWorkerCodec, so this
change requires no IPC schema alteration. Generic local-stream Write/Flush requests
remain used by ConnectionLocalPump; their optimization is separate T1758 work.
At T1759 the hosted benchmark switched to the production transaction baseline;
T1755 artifacts above retain their historical source hashes and three-step baseline.

Verification evidence is recorded in `artifacts/2026-11-22-tunnel/t1759/`.

The new one-completion regression fails on the old implementation and passes with
the transaction. Deliberately omitting the worker flush also fails the permanent
native-stream regression; the correct flush was restored before final checks.
The final focused run passes 224 cases across 14 Android test classes, with no
failures/errors/skips. All 70 measured production methods/constructors/callbacks
in the five maintained transport files have 100% executable-line coverage under
JaCoCo with the repository Kotlin ownership mapper. The Kotlin 1.9.20 PSI checker
measures 493 functions across changed source/fixture files, maximum complexity 9.
All 14 Rust/Android interoperability cases and five benchmark-accounting cases
pass, the benchmark task registers, and Profile compilation passes. These checks
establish the tested transaction behavior, not Android-device CPU/latency gains.

## T1760: optional bounded small-frame gathering

`ConnectionWritePolicy` is independent of the stream/TLS implementation. Its
`gatherPayloadBytes` range is 0–16,384; the default is **0 (disabled)**. The tablet's
USB settings expose `write_gather_bytes` and capture it for the next connection.
Saving leaves the active worker and its policy unchanged. Private preference
schema 2 and worker-spec schema 3 carry the current setting and reject obsolete
schemas; authenticated tunnel framing is unchanged.

With a positive limit, the writer owns one additional byte array of limit + 40
bytes (16,424 bytes at the maximum, excluding array/object overhead). It copies
only eligible nonempty payloads and their encoded header into that scratch array.
Metadata and larger frames use original buffers. The original frame remains owned
until the exact transaction finishes and flushes; gathering does not release
credit early. Partial completions advance within the same scratch bytes. Neither
cancellation nor an expired deadline permits scratch reuse. The single writer
retains its scratch capacity, including old copied content, until overwrite or
owner reclamation; there is no growing queue or per-frame scratch allocation.
Zero allocates no scratch. Native worker retirement obligations remain T1759's.

The exploratory candidate, compared with the T1759 transaction, still reduced
small-frame CPU/record costs but worsened 64-KiB copying. It was replaced by the
actual production policy in the benchmark. Both current modes use the same
FrameWriter and StreamConnectionIo: explicit gathering limits 0 and 16,384.
Each fresh JVM run contains 16 warmup and 48 measured trials, with three
alternating pairs per payload/rate and 60 frames per trial. All bytes and exact
completion identities are checked. Two production runs completed the full domain
with unchanged inputs; their explicit policy settings match the implemented modes.
Only the policy's default was subsequently changed to zero after reviewing them.

| Payload | TLS records/frame, disabled → enabled | 60-fps paired CPU ratio, run 1 / run 2 | 60-fps paired p95 ratio, run 1 / run 2 |
| --- | --- | --- | --- |
| 64 bytes | 2 → 1 | 0.864 / 0.944 | 0.884 / 0.996 |
| 4 KiB | 2 → 1 | 0.982 / 0.974 | 1.060 / 0.894 |
| 16 KiB | 3 → 2 | 0.888 / 0.963 | 0.939 / 0.928 |
| 64 KiB | 6 → 6 | 1.002 / 1.030 | 1.062 / 1.029 |

Native completions including ACK are two per frame in both modes at every size.
Burst small-frame CPU ratios range 0.795–0.947 across the two runs. However, the
64-KiB burst p95 ratios are 1.425 and 1.493, with CPU ratios 1.040 and 1.118, even
though both modes bypass copying for that payload. The cause is unresolved;
T1762 retains allocation/layout, GC, scheduling and JIT investigation. This is why
gathering remains optional and disabled by default. T1759's single native
write/flush transaction remains enabled. These observations do not change the
independent owner-selected 16-KiB WebSocket read default.

Ratios are medians of three matched pairs per run, not confidence intervals or
native-tablet gains. CPU covers the driver and three I/O workers, excluding peer
verification. Timing includes per-frame preparation, handoffs and ACK; initial
writer/scratch allocation is outside the timed interval. Retained capacity is
specified explicitly above, not a measured whole-process peak. The experiment
uses one outstanding frame and private loopback TLS; it does not establish full
reactor, pipelined display, USB, battery or Android-device performance. T1525
retains native/end-to-end acceptance; T1527 retains general allocation measurement.

The final default-zero build passes all 785 cases across 104 selected Android
classes with no failures/errors/skips, including settings UI, current worker IPC,
partial-prefix/cancellation/reuse tests and bounded invalid-input corpora. All 103
measured production methods/constructors/callbacks pass individual 80% line coverage
(minimum 88.9%). The Kotlin/Python counters measure 458 functions in changed source
and fixture files, maximum complexity 9; Profile compilation passes. The integration
run also passed 14 Rust/Android TLS cases and 38 worker/benchmark cases, including
an enabled-gathering worker check before the final default decision. The small-frame
transaction and final default-selection regressions both failed before their
respective changes and pass afterward. Evidence, exact settings, hashes and all raw
measurements are retained in `artifacts/2026-11-22-tunnel/t1760/`.

## T1756: writer integration acceptance

The verified T1759/T1760 implementation has one current production writer owner
(ConnectionSessionRunner), one native stream adapter (StreamConnectionIo), and
one exact WriteFlushed transaction contract. The benchmark uses those same
implementations. AndroidConnectionWorkerRun encodes the selected immutable
worker specification; ConnectionWorkerService decodes the current schema before
constructing the runner. Frame bytes remain within the worker, outside control IPC.

T1759's native fault controls and exact-loan regressions, T1760's 785-case final
connection/settings run and per-method coverage, the 14-case Rust/Android TLS
integration run, and the two fully completed production-policy measurements
satisfy this writer integration item. The current default batches native handoffs
without gathering, and the optional bounded gather setting has explicit retained
capacity and performance limits. T1762 remains open for the measured large-frame
cost. T1757 read-path work, T1758 local-flush work, T1527 allocation measurement,
and T1525 native/end-to-end acceptance remain separate obligations; none is
completed by this writer-only integration. No installed session was changed.
