## Scope and method

[Inventory](artifacts/2026-10-27-c-review/inventory.json): 154 tracked `.c`/`.h`
files, 18,694 lines. This includes production EVDI, accessory and optional GPU
code, the V4L2 ABI probe, tests/fixtures, benchmarks and historical C artifacts.
The vendored libevdi declaration header was inspected as an external ABI
boundary. Dependencies and generated/build outputs were not treated as owned
production code.

[Additional scope](artifacts/2026-10-27-c-review/additional-scope.json) records
four historical `.c.txt` snapshots and embedded C in three Rust/Python test
hosts. Historical before/candidate code was evaluated in its recorded role;
intentional old counterexamples were not reported as new production defects.

All 154 files were submitted to Cppcheck. Manual review concentrated on resource
owners, native handoffs, array/stride arithmetic, failure/cancellation paths,
callback lifetimes, fixture cleanup and independent pixel expectations.
Clang's analyzer additionally covered all 15 EVDI/accessory translation units;
accessory analysis used the repository's fixture libusb declarations.
Neither analyzer's successful exit nor its warning count establishes safety.

Ownership checks followed these boundaries:

- Capture owns the registered source framebuffer. The event loop performs
  native grabs synchronously; conversion workers borrow buffers only through
  completion. Shutdown stops admission and joins workers before freeing storage.
  T1284/T1285 expose the remaining registration cleanup/documentation discrepancy.
- Frame exchange retains immutable writer leases through publication, demand
  changes and mode retirement. A retirement timeout retains storage; it does
  not authorize freeing a live lease. Raw-ring producer and consumer mappings
  have separate kernel references; producer unmap does not revoke the peer's
  mapping. Slot release and generation identities control reuse.
- Cursor adoption transfers allocation ownership, including rejection paths;
  normalized copies and saved backgrounds have separate owners. GPU capture
  uses the X fence and VA surface completion before RGB reuse. Codec references
  retain NV12 frames. T1283 identifies unconfirmed parameter-buffer retirement.
- Accessory helpers own their libusb context/device/interface and transfer
  threads. Whole-process exit is a cleanup sponsor on fatal stream paths; no
  claim was made that a close under an active transfer would be safe.
- JNI wrappers borrow validated direct-buffer ranges. Context handles must be
  null or live handles created by the matching API; forged/stale arbitrary
  handles are outside the existing caller contract. Pure pixel helpers borrow
  initialized storage with validated dimensions, stride and output capacity.

Conservation checks distinguish successful releases from unresolved obligations;
logical ACKs and reference counts were not used as substitutes for native
completion. Eventual cleanup still assumes workers/native calls return or the
owning process is retired. No unrestricted scheduling or leak-freedom proof is
claimed.

repository metric with tree-sitter 0.25.2; grammar-module location and metric

metadata, so no grammar package version is invented.

GPU verification used the already-installed Freedesktop SDK 26.08 with network
disabled. Its newer FFmpeg headers required a command-line spelling substitution
from `FF_PROFILE_H264_CONSTRAINED_BASELINE` to
`AV_PROFILE_H264_CONSTRAINED_BASELINE`; repository source was unchanged. Initial
LeakSanitizer runs failed because of Flatpak's tracing restriction. Repeating
with `--allow=devel` enabled leak detection and all four targets passed. These
results do not certify the project's release SDK or native VA driver behavior.

Not all static warnings were defects: cursor `take` transfers ownership; the
reported raw-ring index is rejected before array access under admitted slot
bounds; checked benchmark assertions perform initialization; the reported
test-file leak overlooks `assert(fclose(...))`; the frame-damage null branch is
the raw-ring path, which does not dereference that transaction token.

This review does not claim fresh per-function line-coverage certification,
ThreadSanitizer coverage, exhaustive interleavings, native Windows acceptance,
physical EVDI/VAAPI behavior or a clean bill of health for external libraries.
Missing native evidence is not treated as passing. Existing platform deferrals
and declined performance campaigns remain unchanged.
