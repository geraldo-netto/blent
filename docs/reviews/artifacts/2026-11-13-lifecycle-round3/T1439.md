# T1439 — retain the original mapping payload through settlement

Input cutoff now removes the device payload from the live sink immediately while retaining its actual native devices under a separately admitted payload owner. The owner waits for the original mapping command's child, output collector, async execution and acknowledged remote outcome before native destruction. It then waits for the original destructor worker/TLS, decrements the touch count once, and joins one sponsored OSK restoration task plus its independent operation receipts. Unknown mapping or cleanup outcomes keep the payload grant and input identity quarantined. Remap/replacement cannot overtake that original work.

The payload pool has 4096 slots, matching the maximum input backend capacity. Each input lifetime reserves one payload observation before effects and admits one payload at a time. The payload slot funds its native destructor and one final async restoration execution; restoration does not reserve another shared task slot after cutoff. The restoration task captures its OSK receipt bag and runtime only, with no reference back to the input lifetime. The lifetime separately retains one original constructor, the payload receipt and two OSK operation observations. This prevents a parent/task self-wait while retaining process-exit sponsorship.

Permanent regressions in `host/tests/input_mapping.rs` cover cancellation with facade loss, cancellation with facade retained, detach/latest-reattach, same-payload remap, normal detach under saturated unrelated task admission, process exit, and unknown mutation after the original child exits. Unit controls cover payload admission overlap, empty payloads, rejected cached-pool initialization, original task join and failed-task quarantine. Existing OSK cancellation/process-cutoff and constructor/identity regressions remain in the normal suite.
