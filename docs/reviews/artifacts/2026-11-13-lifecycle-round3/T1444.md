# T1444 — retain original native mutation acknowledgment

A command child and its output collector can both retire while a delegated D-Bus
setter remains able to mutate server state. The independent private-server probe
in `linux-mapping-review/review.md` reproduces that ordering using the real
installed busctl. Native command receipts alone therefore could release the OSK
gate or input identity too early.

## Implementation and ownership

An observed command port now owns at most one mutation operation. Its existing
input-lifetime or keyboard-operation admission funds that slot, copied bounded
caller arguments, one async task, original command result, child/collector receipts
and a finite outcome state. Production callers provide fixed command names and
validated bounded device/property values; this internal port is not an unbounded
external command-input interface.

The caller retains its existing five-second result deadline. Cancellation or that
deadline drops only the result wait. The original task keeps the new common
retained-execution future alive, including its reply-capable command. Successful
acknowledgment, both original native receipts, and actual original task join are
all required before reuse. No-child spawn rejection is a definitive no-effect
outcome. Queries and subsequent mutations serialize behind the original operation.
There is no task-to-port back-reference or retaining cycle.

Generic post-spawn nonzero exit, signal, I/O/collector failure or lost transport
cannot distinguish every remote rejection from a lost acknowledgment. These
outcomes are logged and retain one bounded quarantine; native exit is not treated
as remote settlement. This is an explicit conservative CLI-adapter limitation.
Test-only AcknowledgedCommands models isolated local fake programs whose exit
independently settles effects, preserving definitive rejection/retry controls.
Query-only SystemCommands rejects mutation before starting effects.

KWin setters use an explicitly owned port. Busctl requests an infinite native
reply timeout so its ordinary 25-second timeout cannot destroy the only reply
while the caller has already returned. Qdbus retains its own intrinsic timeout;
an ambiguous failure remains unknown. Successful xinput map-to-output exit crosses
its XSync boundary; failed/interrupted execution is conservatively unknown.
Native source references and installed versions are in the probe report.

The common retained API changes neither output/stdin limits nor admission grants.
Dropping that low-level future still initiates native retirement, so it must be
retained by the higher-level mutation owner. Existing bounded command APIs remain
bounded. See `T1444-common.md` for the separate common execution verification.

small test-local request adapter initially invoked the existing output API, then
invoked the new mutate API without changing the ownership assertions. Both failed
before the fix (`T1444-native-red.log`) because cancellation/deadline prematurely
retired an unacknowledged Set. Each fixture releases the server and settles original
receipts before reporting the defect assertion. This reproduces production
miscomposition, not a defect in the bounded query API's own contract.

## Limits and conditional cleanup

This validates private D-Bus delegation and isolated native-process ownership;
it does not claim physical compositor/Xorg/device acceptance. No suspend, live
service restart, driver change, tablet configuration or live input was performed.
Windows native lifecycle validation remains blocked as previously recorded.
Eventual cleanup requires the retained original command to return an acknowledged
outcome and native workers to settle. Actual lost outcomes remain owned/funded,
possibly preventing reuse or process drain; no timeout fabricates settlement.
