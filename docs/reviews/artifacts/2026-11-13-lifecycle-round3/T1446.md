# T1446 — resolve the creation name in every X11 helper

The X11 mapper now passes the exact observed creation name as one argument to both `map-to-output` and `list-props`. It does this for initial mapping, initial readback and cached readback. Numeric IDs remain listing/cache keys and diagnostic data; cache preparation still checks the admitted current name before reuse. This closes the reproduced cross-helper reassignment: a listing gives the owned creation ID 41, the next helper sees foreign ID 41 and the owned creation ID 42, and both mutation/readback now select 42 by name.

## Ownership and limits

The production change adds no new retained state, admission pool, task, callback or cleanup sponsor. The immutable creation name is borrowed from the existing bounded payload identity; command submission copies arguments under the existing command owner. Original command, collector and acknowledged-outcome proofs still gate payload retirement and identity reuse. A cached numeric key cannot become a command selector. Initialization, rejection and cancellation retain T1439/T1444 ownership, including the independently funded restoration task.

The ambiguity fixture returns a generic post-spawn nonzero status. Production correctly leaves it unknown and retains the funded payload; it does not infer acknowledged rejection from fixture-specific knowledge. That isolated test reaps the original command and intentionally retains one fake payload through process teardown. Successful reassignment settles the original command and one fake create/destroy pair. No real input device, X server, compositor or tablet was manipulated.

The official [xinput 1.6.4 source archive](https://www.x.org/releases/individual/app/xinput-1.6.4.tar.xz), SHA256 `ad04d00d656884d133110eeddc34e9c69e626ebebbbab04dc95791c2907057c8`, confirms the native selector contract: `src/transform.c:314–330` and `src/property.c:538–577` resolve the supplied selector; `src/xinput.c:309–346` queries the current registry, treats only all-digit selectors as IDs and rejects duplicate exact names. Normal helper exit follows XSync/XCloseDisplay (`src/xinput.c:431–435`). This establishes fresh exact-name resolution per helper, not atomicity against arbitrary registry mutation inside one helper between lookup and effect. The private protocol model proves the reproduced ordering; it is not physical Xorg restart evidence or new backend support.
