# T1443 — atomic daemon PID publication

`Publication::new` previously wrote the final PID path before constructing its
cleanup guard. A private process with RLIMIT_FSIZE=2 returned EFBIG after leaving
`14` at that path for PID 1430277. This is a misleading hint and failed-startup
cleanup defect. PID consumers separately verify daemon identity; this finding
does not establish that an unrelated process could be killed.

Publication now writes an owned same-directory `NamedTempFile`, then persists it
only after the complete PID has been written. A failed write leaves an absent
destination absent and preserves an existing hint. Failed publication drops the
temporary owner; successful publication transfers the final path to the existing
PID guard. Successor-PID preservation and cancellation/unwind cleanup remain.
This reuses the existing tempfile dependency, with no compatibility path or new
background owner. It adds one temporary file per in-progress publication, holding
only the bounded decimal PID. This is atomic visibility, not crash durability or
an atomic cross-process compare-and-delete claim.

Permanent tests were added to `host/src/daemon_pid.rs::tests` before behavior
changes. The partial-write test fails against the original module, both with no
hint and with a prior hint (`T1443-red.log`, `T1443-prior-red.log`). Four unchanged
cleanup/publication controls pass before the fix. Independent review improved
the fixture to constrain the write below the actual PID length, including
one-digit PIDs in private namespaces; it changes only the child process's limit
and signal disposition and restores both before assertions. The final permanent
source also fails against the original publication body
(`T1443-final-source-red.log`). No assertions were weakened.

The exact production module and its permanent tests were compiled directly with
`rustc --edition=2021 --test -C instrument-coverage` while other agents owned the
Cargo lane. `T1443-harness.rs` includes that module and the unchanged production
PID-removal helper; there is no alternate publication implementation. Existing
matching tempfile, Tokio and libc rlibs supplied dependencies. All 6 top-level
tests pass after the fix; nested child runs are not counted again. The normal
suite retains these tests under the daemon binary's existing test module:

```text
cargo test --offline --locked -p blent --bin blent daemon_pid::tests -- --nocapture
```

`T1443-metrics.json` and `.lcov` retain exact-source native counters from the final
harness object: `Publication::new` 12/12 lines and `Drop::drop` 3/3 lines.
All 10 functions in the production/test module have complexity at most 3;
all 3 retained review/harness functions are also measured and below 9.
Tools: Rust 1.100.0, LLVM 23.1.5, repository per-function coverage inventory and
syn 2.0.119 complexity frontend. Raw profiles, executables and dependency command
paths remain external under `/tmp/blent-pid-partial-review`.

Only owned temporary directories were used. The fault does not constrain the
agent, daemon, installed applications or sibling tests. Temporary cleanup still
depends on filesystem removal being permitted; the tested write/publication
failures leave no staging files. No physical device, service or deployment was
involved.
