# T1435: Linux GUI process-exit ownership

The GUI platform adapter runs the Linux eframe workflow inside the existing
`runtime_owner::run`, on the original calling thread. Normal window closure,
errors and unwinding therefore retain admitted media/control workers through
original native thread and TLS completion before process exit. The adapter returns
the original GUI result and resumes the original panic; runtime creation errors
become eframe application-creation errors. Non-Linux entry remains a direct call.

This reuses T1432's process admission cutoff, shared configuration queue shutdown
and original-proof drain. There is no new pool, registry or duplicated stop state.
The synchronous eframe closure runs on the calling thread rather than a spawned
Tokio task; controllers must finish their workflow/drop handoff before it returns.

## Permanent red and green

First extracted a behavior-neutral platform adapter whose body directly invoked
the workflow, and routed actual `main` through it. Then added the normal-suite
headless regression before changing lifetime behavior. `T1435-red.log` records
its expected failure: GUI entry returned while the original camera/control/TLS
proof remained pending and its pool slot was still active. Gates were released,
the entry thread joined, and original completion observed before the assertion.

```text
cargo test --offline --locked -p blent-gui --bin blent-gui platform::lifetime::tests::t1435_gui_entry_retains_camera_and_original_control_thread -- --nocapture
```

After applying the Linux process owner, 2/2 selected normal unit tests passed
(`T1435-green.log`). They execute six isolated controller scenarios: normal,
error and panic workflow outcomes, each with an original native-body gate and
an original TLS-destruction gate. Every case verifies calling-thread identity,
original pending proof/active slot before release, and eventual original completion
and zero active slots after release. A seventh child scenario verifies invalid
runtime capacity rejects startup before invoking the GUI workflow. These seven
child executions are not seven additional Rust tests.

The permanent actual-entry integration test passed 1/1
(`T1435-native-green.log`). It launches the real GUI binary, creates its actual
eframe window on an owned Xvfb, sends WM_DELETE_WINDOW only to that process's
window and verifies exit 0. It does not invoke Cargo recursively.

The first version of that fixture stalled before Python/GUI startup: `xvfb-run`
was PID 1 in the private namespace, waiting for Xvfb readiness. Inspection showed
the launcher waiting with only the X server child. The corrected init shell starts
`xvfb-run` as a child and waits for it, preserving namespace teardown as final
containment. The owned stalled namespace was explicitly terminated; its failed
run is retained in `T1435-native-before-init-fix.log`. This was a fixture startup
problem, not a GUI production failure.

## Ownership audit and limits

The workflow owns its GUI/App/controllers. Camera/audio drop handoffs transfer
original worker ownership to the existing retained reaper; process retirement
observes those original proofs until native and TLS destruction finish. Cutoff
rejects later admissions while the runtime stays alive for admitted cleanup.
Unwind and error outcomes are retained until that drain, rather than destroying
the executor while cleanup still depends on it. Eventual exit remains conditional
on original native work and cleanup finishing; no deadline grants release.

Six adjacent GUI files were inspected for other exit effects: `main.rs`,
`platform/linux.rs`, `status_worker.rs`, `status_poll/linux.rs`, `settings.rs` and
`media_owner.rs`. The new adapter does not register raw status/update/action
threads. Status/update work and intentionally detached daemon launch retain their
existing contracts; settings explicitly permits process interruption at its atomic
old/new configuration boundary. No additional concrete defect was confirmed by
that source-only inspection. This fix is the admitted media/control process fence,
not a claim that every GUI effect is registered or that OS termination is graceful.

The actual-entry fixture uses private user/PID/mount/network namespaces, a private
D-Bus session and Xvfb, private HOME/XDG paths, and fake ADB/systemctl commands.
It bind-masks `/dev/uinput` and `/dev/dri` when present and forces software rendering.
Direct-child cleanup plus namespace teardown contains descendants on fixture failure.
No live service, user display, tablet, native input device or media device was used.
