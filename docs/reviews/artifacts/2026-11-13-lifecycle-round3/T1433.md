# T1433 — original OSK command and operation ownership

OSK synchronization now retains both original command receipts (child and output
collector), and its owned keyboard-operation mutex guard, through cancellation.
Input lifetime observes the operation's completion separately from constructor
and final-task completion. KWin calls use an explicit command port; existing
non-OSK callers retain their current adapter until separately addressed.

The shared gate also serializes direct daemon restoration with input add/remove
and final restoration. Direct daemon restoration's independent process-exit
sponsor is T1441; mapping commands and original input-device payload retention
remain dependent T1439. This item does not claim those separate outcomes.

## Ownership, funding and cleanup

The global OSK gate remains the single serialization owner. Its fixed two-receipt
pool funds one serialized operation and the predecessor's completion-publication
gap. The owned mutex guard prevents another operation from creating commands until
both original command proofs settle. These receipts are independent of task
admission: a final restoration task with the sole task slot does not compete with
its own OSK operation. A permanent capacity-one process test verifies this.

Before command effects, `ObservedCommands` reserves exactly two observation slots.
The shared command adapter synchronously binds collector and child proofs before
yielding. Unused reservations drop on failed creation; bound proofs survive async
caller cancellation. The next command waits those exact proofs, so a failed
backend probe cannot start a fallback over unknown original work. The existing
command deadline bounds the command attempt; it is not retirement evidence.

Each input lifetime separately funds two constructor/final-task receipts and two
OSK operation observations. Observation rejection occurs before keyboard command
effects and is reported; original receipts remain owned. The final restoration
task retains the admitted input lifetime and observes its own OSK operation. Its
retirement depends on the distinct command proof set, never the enclosing input completion
that includes the final task. Thus the task/lifetime relationship has no self-wait
cycle. Process cutoff rejects new input admission while already-admitted cleanup
continues under that original sponsor.

Cancellation transfers the original guard and command observations to the bounded
retirement owner. Proof completion, guard destruction and admission reuse remain
separate ordered boundaries. Neither an async result, timeout, empty output nor
reference count settles an unknown child/collector. Success, failed creation,
caller loss, cancellation and exhaustion retain explicit cleanup ownership; no
unbounded queue or command history is introduced. Cleanup is conditional on
actual original child/collector settlement and scheduler/reaper progress. Native
failure that never settles intentionally retains the bounded operation and gate.
