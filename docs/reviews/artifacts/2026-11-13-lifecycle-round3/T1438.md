# T1438 — recover failed initial session identity observations

Known logind owners retain conservative power/lock observation when initial
session discovery fails. GetSessionByPID/GetSession failures and malformed User
or session-path evidence request the existing source replacement workflow;
explicit NoSessionForPID/NoSuchSession or unsupported lookup replies remain
absence. A validated foreign UID remains absence and is never followed.

Session-ID fallback now follows explicit lookup absence. A transient PID lookup
failure remains unknown, since a missing fallback cannot establish that the
original process has no session. Current callers, configured ID bounds and UID
validation remain in place. The private fake manager now emits actual login1
absence names; generic Failed is no longer used to represent definite absence.

The existing single acquisition deadline covers stream setup, state/session
queries and original-owner validation inside Actor::logind. Expiry after the
known stream owner is acquired retains a failed initial snapshot. Removing the
outer duplicate deadline prevents discovery from discarding that known observer.
No deadline was expanded, and no retry loop or resource grant was added.

Actor/source ownership remains unchanged: one original connection and bounded
signal streams belong to the admitted source; stop closes that exact connection.
Following retains each attempt's original completion, including held test debt,
before a new candidate can be created. T1442 rejects failed initial evidence with
the independent retry marker, before continuity learns any provisional support;
only successful creations publish an epoch. Errors and deadline expiry change
observed state, not native settlement. The new pure payload validators own their bounded
message/object values and transfer only a validated session path; foreign or
invalid evidence creates no native owner.

## Regression evidence

`T1438-red.log` records five permanent private-bus tests before production edits:
four recovery/stop cases fail and the explicit absence/foreign-UID control passes.
The independent public PowerFactory/Following probe establishes the defect beyond
an assertion deadline: the same native owner later reports the current UID and
LockedHint=true, while Blent retains lock capability=false and display demand=true.
Its separate delayed-User mode also loses power capability at the acquisition
deadline. Source has no failed-initial flag and no retry on either old path.
See `linux/T1438-review.md` and its source/log/complexity evidence.

The permanent regressions cover initial PID, fallback session and User read
errors; User deadline expiry; repeated failures; original proof blocking retry;
fresh validated locked state followed by an unlock signal; explicit stop; actual
no-session and foreign-UID controls. Native unit tests cover definite absence vs
transient error names, malformed identity values, session path bounds and UID
validation. All buses and fake services are private. No live desktop, tablet,
input device, service, driver, suspend or configuration was touched.

The intermediate draft retained provisional lock support. Its new recovery-to-
explicit-absence control failed (`T1438-draft-green.log`), prompting the separately
committed T1442 prerequisite. This final source uses that admission contract:
initial failure requires Publication::Failed; a later genuine no-session or
foreign UID may recover to unsupported lock observation. Previously validated
capability continuity remains unchanged.

`T1438-green.log`: 71 activity tests pass. `T1438-coverage.log`: 86 instrumented
tests pass (71 activity, 12 follower, 3 activity-view), including all eight new
T1438 tests. The restored T1442 prerequisite and its explicit first-error controls
remain part of that run.
