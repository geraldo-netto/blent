# T1441 direct keyboard restoration process ownership

Direct daemon restoration now reserves a one-slot `osk::Restoration` owner after
configuration/build validation and the startup checkpoint, before runtime/PID or
device effects. Shutdown consumes that original reservation after cutoff. The old
unsponsored `osk::restore()` API is removed and all current callers are updated.

`Restoration::run` is a cleanup workflow: it waits for original operation
settlement on both normal completion and an internal command-result timeout.
It can remain pending indefinitely when the original outcome is unknown. This
does not change `CommandPort`'s five-second result deadline. Cancellation transfers
the same original operation proof to process retirement, retaining the runtime.

with the explicit reservation API. The normal control additionally rejects a

observations, not kill deadlines. Original completion after release has no

## Ownership audit

The direct sponsor pool owns one admission; the process registry holds only its
original completion observation. The observation grant and permanent exact-bound
test increase together from 12420 to 12421. The extra slot is a singleton daemon
cleanup obligation, independent of the existing input-owned OSK cleanup sponsor.

Before acquiring the keyboard gate, cancellation has no keyboard effect and drops
the unused admission immediately. After acquisition, the owner binds the exact
operation completion before `restore_unlocked` can execute or await an effect.
The T1444 operation proof includes original child/collector retirement, actual task
join and acknowledged mutation outcome. A deadline, native exit alone or an empty
snapshot cannot publish this proof. Cancellation after that handoff moves the
admission and proof to the existing retirement owner; no replacement process
admission is requested during cleanup.

The pending observer owns only the exact completion, with no back-reference to
the restoration owner, operation or input lifetime. The operation retains its
existing command owner and keyboard guard. Duplicate/exhausted admissions reject
before effects. Startup errors/unwind drop unused reservations; process cutoff
rejects later creation. The local gate-exhaustion control proves rejection releases
the unused sponsor and permits recovery. The existing runtime owner retains Tokio
until all admitted proof observations settle, including cancellation and unwind.

Safety is bounded retention of the original obligation, not unconditional eventual
exit. Eventual reuse/exit requires original execution and acknowledgement to become
observable. Unknown remote outcome remains funded and quarantined. This change
does not recover uncatchable process termination or supply unavailable native
Windows/device validation.
