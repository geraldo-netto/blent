# T1434 — retain failed touch release debt

The Linux input sink now retains the original possible contact mask through any
failed touch frame or release. Before publishing another valid sample, it must
successfully release that mask through SYN and flush. Contact coordinates commit
only after successful publication. A replacement controller can acquire its
logical generation while physical publication remains closed by original debt.
Invalid actions/slots cause no effects. Pen behavior is unchanged.

Changed production: `host/src/input/linux.rs` (eight maintained functions).
Permanent normal-suite regressions: `host/src/input/batching_tests.rs`.

## Ownership and bounds

The existing `Mutex<InjectDevices>` remains the single serialization owner.
`active_slots` means possible original native debt; `touch_contacts` is committed
contact state. Their meanings differ deliberately. A one-bit recovery latch
prevents any fresh publication while the original outcome is uncertain. A staged
copy of ten contact entries is stack-local and never escapes. Existing bounded
native frames remain at most 24 events for all ten slot releases, below the
64-event buffer capacity; no retry queue, worker or history allocation is added.

Admission occurs only after slot/action/device validation and, when needed,
confirmed recovery. The latch and possible-slot bit are armed before native I/O.
Success commits coordinates and retires an UP bit; failure preserves the old
committed coordinates and conservative debt. Release attempts are idempotent for
owned slots and clear state only after the entire frame succeeds. Superseding
controllers share this same gate. Stale controller leases cannot release their
successor's contacts. Native device destruction is the final settlement boundary.

No references escape, retaining cycles or additional cleanup sponsors are added.
Cleanup is conditional on a later successful explicit release/sample recovery or
device destruction; persistent I/O failure safely retains bounded debt and denies
fresh publication. This is intentional ownership, not an eventual-cleanup claim
without external recovery. Original hardware failure behavior is not validated
on a physical uinput device; fake-writer faults and fail-closed adapter tests are
the evidence scope. Declined stylus work and other blocked native evidence remain
unchanged.
