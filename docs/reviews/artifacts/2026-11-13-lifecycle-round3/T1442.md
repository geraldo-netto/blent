# T1442 — admit capability history only after initial evidence

A failed initial display read previously created a supported display actor and
permanently taught Continuity that display observation was available. A later
explicit unsupported reply (mode -1 or UnknownProperty) was then rejected as
capability loss, even though display support had never been validated. The
permanent private-bus regression fails on the restored pre-fix implementation:
mode -1, three creation attempts and Publication::Failed persist instead of
recovering to explicit unsupported observation (`T1442-red.log`).

Backend inclusion now reports initial evidence eligibility. LinuxSource starts
and owns every admitted actor, then rejects a candidate whose initial evidence
requires recovery. The independent RetrySourceCreation error requests retry
without publishing an epoch or capability. Following handles only that marker as
retryable on the first attempt; ordinary initial errors, panic and creation
timeouts retain their terminal behavior. Every retry still waits for the exact
original SourceLifetime completion and the existing backoff, with stop taking
priority. Continuity sees only successful initial evidence; previously validated
capabilities remain sticky and conservative across owner loss.

The marker has no allocation or native state. The source remains the sole owner
of its bounded actor tasks, connections and original completion proofs. Rejected
candidates stop/drop those owners through the established partial-source cleanup
path; no new cleanup sponsor, resource grant, synthetic epoch or retry loop was
introduced. The display/native and DPMS adapters implement the explicit internal
eligibility contract; public OS-independent Source capabilities are unchanged.

## Permanent regression and contract updates

The new native regression covers transient first display failure followed by
both explicit mode -1 and missing-property outcomes. The independent follower
regression holds the failed creator's original completion and proves no second
attempt occurs before release. It then accepts a real fresh source and retires
it. Existing first-error controls, stop with held native debt, repeated initial
power/lock/display failures, initial unsupported behavior and all 64 capability
subset transitions remain in the selected cohorts.

Initial failed candidates now publish Failed, not an Observed lost snapshot.
Existing T1429/T1436 initial-error regressions were updated to require Failed;
original-debt assertions, creation counts, successful recovered state, later
signals and stop controls remain. Such rejected candidates expose no source
epoch, so comparisons against an unpublished failed epoch were removed; existing
fresh-epoch replacement controls remain unchanged. T1427's established source
still publishes its original lost observation, then failed replacement attempts
publish Failed. This is an intentional admission contract correction, not a
relaxation of native settlement or display demand checks.

The first implementation used an ordinary error, exposing the existing terminal
first-error policy; `T1442-before-typed-retry.log` retains that diagnostic result.
The later test diagnostic expected three attempts even though correct recovery
stops at two; only that diagnostic wait changed. Its unsupported capability and
demand oracle is unchanged (`T1442-before-attempt-diagnostic-update.log`).
