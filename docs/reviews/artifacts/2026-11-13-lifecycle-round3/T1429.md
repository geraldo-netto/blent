# T1429 — retry failed initial logind boolean snapshots

Initial PreparingForSleep, PreparingForShutdown and LockedHint reads now retain a
bounded failure marker with their original native flag. A transient query error
or invalid boolean value leaves the corresponding state unknown and requests the
existing actor-loss/replacement workflow. The factory has admitted that source's
capabilities, so replacement cannot silently discard them. The original actor and
attempt must settle before another creation; retry/backoff/capacity remain owned
by the existing follower.

Explicit UnknownProperty, UnknownInterface and UnknownMethod replies retain the
current supported-field unknown/non-retry behavior. An absent service remains
explicitly unsupported as before. This does not infer running, unlocked, or absent
native resources from failed observation. The failure markers allocate no native
resource, contain no references and live only with the original source flags.
Original stop remains authoritative before the watcher's recovery decision.

## Regression evidence

The initial-error and stop-with-held-native-debt regressions were added before
production changes. `T1429-red.log` records both failing while the explicit missing
property control passes. The independent public-API probe in
`linux/initial-query-failure.log` demonstrates why: one initial query fails, no
retry occurs, and a subsequent same-owner query succeeds while publication stays
PowerUnknown. A test timeout alone is not the causal evidence.

Permanent controls now cover all three boolean fields, multiple failed epochs,
original completion held across attempted retry, fresh-epoch recovery and actual
current state, stop while original debt remains held, explicit missing property,
invalid boolean type, and the seven classified D-Bus error names plus an untyped
error. Every counted replacement asserts all prior original attempt proofs have
completed. Existing owner/transport loss, absent-owner, unsupported startup and
successful same-source refresh regressions remain intact.

`T1429-green.log`: 59/59 selected activity-related tests pass.
`T1429-coverage.log`: 73/73 instrumented tests pass (activity59, follower11,
