# T1428 — retire PID publication on startup failure

The daemon workflow now retains a scoped PID publication. Its destructor uses
existing PID comparison before removal on normal return, error, cancellation or
unwind. A different PID published before cleanup is preserved. PID files remain
process-discovery hints; this is not a new cross-process compare-and-delete
primitive or native-resource retirement fence. Uncatchable process termination
remains outside destructor cleanup.

The permanent namespace fixture was added before changing production behavior.
`T1428-red.log` records exit 1 and an unwanted remaining PID after a deliberately
invalid activity admission limit. The same fixture passes after the fix, retaining
the original startup error and removing the file. `daemon_startup.rs` executes it
in the normal Cargo suite alongside the existing six actual-daemon signal cases.
The private user/mount/PID namespace masks /dev, disables input, uses fake ADB,
private HOME/configuration/runtime and nonexistent D-Bus addresses; no live
application, device or service is controlled.

`T1428-coverage.log` records 14/14 selected Rust tests passing: PID publication 3,
shutdown listener 2, daemon activity 5, remembered tray shutdown 2, and namespace
startup 2. The new unit controls cover normal removal, replacement preservation,
failed creation, unwinding and cancellation after publication. Original child
processes are reaped; namespace teardown contains descendants on fixture failure.
The publication owns one path and PID, with no shared mutable state, native handle,
callback, retained task or borrowed view. Drop ends publication ownership; the
existing process registry separately retains native cleanup.
