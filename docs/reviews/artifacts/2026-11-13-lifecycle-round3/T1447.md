# T1447 current atomic update API

Rust 1.100.0 deprecates `Atomic::fetch_update` as renamed to `try_update`.
`T1447-warning-before.log` retains the compiler's six default-build diagnostics
from `/tmp/blent-t1446/unit-red.log` (original SHA-256
`4f3c1520e8518a52f70ce7b2e4ee9bb21b27fc8d5c472df88cef582965369b22`).
Source inspection found two additional calls gated by `inproc-encoder`.
The project development instructions select stable Rust; no older compiler/MSRV
contract or toolchain pin was found in the workspace/package manifests.

The eight calls now use `try_update`. Atomic success/failure orderings, closure
logic, checked arithmetic, returned values and error handling are unchanged.
No compatibility shim or warning suppression was introduced. This is compiler API
maintenance, not a claimed runtime behavior fix; the prior warning evidence is
not presented as a behavioral regression failure.

`T1447-api-replacement-initial.json` describes the initial eight literal method-name
substitutions only. The final scope also includes a narrow encoder nonce helper
and permanent boundary control, explained below. Final source identities are in
`T1447-coverage.json`, including `encoder_worker/tests.rs`.

## Ownership and bounds

Existing admissions remain authoritative for retirement, configuration requests,
media bytes and viewer subscriptions. Their original limits, release paths and
atomic publication orderings are unchanged. Activity epochs and encoder/raw
nonces retain checked increment and rejection at exhaustion; no wrapping/reuse
path is added. The helper only borrows its counter during one atomic reservation,
retains no reference and allocates no owner or storage. The new test owns its local
counter for the entire finite `MAX-1`/`MAX` sequence. No native-resource handoff,
cutoff, quiescence or settlement boundary changes in this maintenance item.
