# T1446 — numeric selection crosses X11 server incarnations

Confirmed controlled protocol counterexample, medium severity/small effort; separate from T1445's stale creation-name match. One actual LinuxBackend owns one fake native payload. Its listing helper returns the current creation at ID 41. The next private mapping helper models a new server registry where 41 belongs to a foreign device and the still-owned creation is 42. Production sends `map-to-output 41`, the fixture records the foreign mutation, and production reads properties by 41 too. All fake native work settles: one creation/destruction and original command PID reaped.

`probe.log` retains this trace. The fixture is a server-incarnation model, not a live Xorg restart. It verifies marker 497 before constructors and uses private commands/sysfs/uinput files. `provenance.json` identifies the exact e4bcb6f1 library used before behavior changes. `complexity.json` measures the retained probe and fixtures; generated binaries, profiles and dependency manifests are external.

Source chain: `map_x11_list` resolves `(id,name,kind)`, then `Mappings::map` passes the numeric ID to map-to-output; `properties` also uses that ID. These independent helpers reconnect to the display and therefore do not retain a server-incarnation binding. Distinct creation names alone do not change those numeric selectors.

Required permanent regression: list a current creation under an old numeric ID, reassign it to a foreign registration before the next helper, and require both mutation and property readback to address the exact current creation name. Preserve cache hit/invalidation, delayed registration, failed mutation, ambiguity and native retirement controls. Native generic nonzero outcomes remain unknown under T1444 even when a fake explicitly knows that it rejected before effects.

The official [xinput 1.6.4 archive](https://www.x.org/releases/individual/app/xinput-1.6.4.tar.xz), SHA256 `ad04d00d656884d133110eeddc34e9c69e626ebebbbab04dc95791c2907057c8`, supports exact-name addressing: transform.c and property.c resolve selectors through xi2_find_device_info; xinput.c distinguishes numeric IDs from names and rejects duplicate names. This supports a fresh exact-name lookup in each helper. It does not establish atomicity against arbitrary registry mutation between lookup and effect inside one helper.
