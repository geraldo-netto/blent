# T1440: Linux Wi-Fi CLI catchable cancellation

The Linux Wi-Fi command now creates the existing signal listener before polling
setup. `Listener::cancel_on_signal` selects the owned command against the remembered
SIGINT/SIGTERM request. A signal closes admission and drops the command future;
existing process/runtime and Wi-Fi owners retain original creation and cleanup.
An interrupted command prints `Command interrupted` and exits with status 1.
Normal success stays status 0, and unrelated errors retain their diagnostics.
Daemon graceful-stop semantics and other CLI commands are unchanged.

The CLI-local `setup_wifi` owns command signal lifetime; shared Wi-Fi policy and
its platform setup remain independent of process signals. This is a needed entry
adapter, with one existing listener/request state owner and no compatibility path.
`docs/faq.md` documents the interruption outcome and possible cleanup wait.

## Ownership and limits

The retained listener owns one request channel and one observer task. Registration
precedes the first setup poll. Its request flag is published before admission
cutoff, so the existing typed shutdown-error classification cannot outrun its
reason. The cancellation selection drops the original setup future before the
CLI returns to runtime teardown. Dropping the waiting attempt closes its original
decision channel; the independently retained native attempt finishes its original
creator and compensating cleanup. Process exit waits for that native lifetime.
No new configuration request is admitted after the existing process cutoff.

This changes neither endpoint lease ownership nor its capacity. Existing
reservation/creator/cleanup identities remain authoritative; caller cancellation
is not treated as native quiescence. Cleanup liveness is conditional on original
native work and evidence eventually settling. The change cannot make arbitrary
native I/O interruptible, and does not promise cleanup after SIGKILL.

Fixtures use private user, PID, mount and network namespaces, private HOME/XDG
paths, and a PATH containing only the file-backed fake ADB. They release gates
and reap the direct CLI; PID namespace teardown is the final descendant containment
boundary on failure. No real ADB server, tablet, service, GUI or device was touched.
These are Linux entry-point changes; no Windows native acceptance is claimed.
