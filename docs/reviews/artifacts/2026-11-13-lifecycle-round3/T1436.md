# T1436 — retain known display observation after initial query failure

A known compositor owner whose initial snapshot fails now remains a supported,
unknown display observer. Transient query errors, malformed modes and snapshot
deadline expiry produce a failed initial flag; the existing actor/follower
replacement workflow keeps demand conservative and waits for exact original
native settlement before another epoch. Explicit missing-property/interface/
method replies and compositor mode-1 retain the unsupported result.

Display acquisition keeps one absolute deadline, shared by stream setup, property
read and final original-owner validation. The outer duplicate timeout was removed
from discovery so it cannot discard a known owner's failed snapshot. This does
not expand the deadline or introduce a separate retry loop, owner or native
resource capacity. The actor retains its original connection/streams; ordinary
source/task receipts govern stop, cancellation and replacement.

## Permanent regression and contract update

Before production edits, `T1436-red.log` records the initial-failure/recovery and
held-original-stop tests failing; the explicit unsupported control passes. The
independent public-API probe in `linux/initial-display-failure.log` shows the
causal defect: an existing compositor with display-off mode3 fails one Get, then
Blent permanently reports display capability false and demand true, despite the
same owner's later successful Get. Finite timeout alone is not the evidence.

Permanent tests now cover a transient error, query timeout and invalid mode;
original native debt blocking retry; fresh display-off recovery followed by a
valid active signal; explicit stop with held debt; and missing-property/mode-1
unsupported controls. Existing absent-owner and fresh/failed lock observations
remain in the selected suite.

One previous T1427 assertion expected Publication::Failed after discovery threw
away a failing display actor. The new contract deliberately retains the known
owner's authority and publishes Observed with source_lost instead. The assertion
now requires display capability=true, source_lost=true and display demand=false;
retry-count, original-proof and stop assertions remain intact. The intermediate
61/62 result is retained in `T1436-green-before-contract-update.log`; no demand or
lifetime check was removed or weakened.

`T1436-green.log`: final62/62 activity-related tests pass.
`T1436-coverage.log`: final76/76 instrumented tests pass (activity62, follower11,
activity-view3). All native observations use private fake buses. No real display,
suspend, input, driver, tablet, configuration or live service was changed.
