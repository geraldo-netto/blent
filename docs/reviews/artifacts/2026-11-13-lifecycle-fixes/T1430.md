# T1430 — reject unrepresentable Linux input identities

The Linux input boundary explicitly admits instance IDs 0..=4095. Each instance
uses one group of 16 u16 product IDs; its three device names and product IDs
remain distinct throughout that domain. `DeviceIdentity::for_instance` now returns
InvalidInput before arithmetic for larger values. Backend admission validates the
identity before claiming its single follower, and rejects through the existing
completed-follower path. `InputConfig` documents this Linux boundary. Current
synthetic mapping/constructor callers consume the checked result explicitly.

The previous API panicked on 4096 (product multiplication) and u32::MAX (name
suffix addition) with overflow checks enabled, even for display-only configuration
and an unpolled follower. Other out-of-domain values silently wrapped product
arithmetic in unchecked builds. Normal daemon display slots remain within the
supported range; this is boundary validation, not a four-tablet capability change.

`host/tests/input_creation.rs::t1430_identity_boundary_rejects_without_panic_or_admission`
was added before behavior edits. It failed with the original overflow panic
(`T1430-red.log`), then passed unchanged. It covers valid endpoints and invalid
4096/65535/65536/MAX values, no-device execution, rejection before follower claim,
subsequent valid admission on the same backend, and original completion after
drop. It checks the fail-closed uinput shim marker before any backend construction;
its fixture records zero native device creation/destruction.

The permanent pure identity property test exhausts all 4096 admitted instances,
checking 12288 distinct names and product IDs against independent affine expected
values. It also checks four invalid boundaries and 256 generated invalid values.
This bounded test's temporary sets are owned locally and released on test return.
The six existing T1422 original-constructor/cancellation/session/process/limit
regressions remain unchanged and pass with the new boundary case.

Final native counters, exact objects, source hashes and scoped complexity are
recorded in `T1430-metrics.json` and `T1430-complexity.json`. The selected eight
cases pass (`T1430-green.log`, `T1430-coverage.log`). Instrumentation uses Rust
1.100.0, cargo-llvm-cov 0.8.7 and the project's syn2.0.119 source inventory. The
first coverage attempt reused an uninstrumented integration object; it was rejected
as missing counters. Touching source mtimes (without changing bytes) forces the
workspace wrapper to rebuild that object. Final profiles and frozen binaries stay
outside the repository; only the successful exact-object export is reported.
All three maintained production functions have 100% executable-line coverage:
admit 5/5, follow 20/20 and for_instance 20/20. All 202 functions in the scoped
changed-source inventory measure at complexity <=9 (maximum 9).

The existing process-owned Lifetime remains authoritative for identity claim,
native constructors, cleanup observations and admission reuse. Validation adds no
persistent allocation or second mutable owner. Invalid input returns before
claiming the identity, starting native work or computing a wrapping product/name.
Successful IDs keep the original retention/settlement behavior and permanent
quarantine rules. No shim, fallback, migration or old unchecked constructor remains.

These are source, pure-property and private syscall-fixture results. No physical
uinput device, live desktop, tablet, service or settings were changed. The separate
OSK/mapping-command fence gap T1433 and touch-release debt T1434 remain separate
findings; this item does not claim to resolve either.
