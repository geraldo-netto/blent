# T1417 — separate command response from service cleanup

The shared deadline model now names the unchanged 35-second managed-command
response budget directly. It no longer claims a 15-second systemd stop deadline
or an ExecStop phase. The retained T268 regression verifies both client branches
and the accepted infinite service-cleanup policy, including no forced SIGKILL or
ExecStop. Native ownership and cleanup behavior are unchanged.

The existing regression failed before the edit with ParseIntError on `infinity`
(T1417-red.log). The updated regression passes (T1417-green.log), as does the
existing template/renderer policy test (T1417-policy.log). This is correction of
an obsolete test/model against T1412's accepted contract, not a runtime timeout
change. No live service was stopped or reconfigured.

The pure `daemon_command_timeout(bool)` function has no retained resources or
borrowed state; its two possible outputs remain bounded durations. Both branches
were executed by the permanent test under LLVM instrumentation: 5/5 executable
lines, 100%. Its cyclomatic complexity is 2; the changed test scores 3. Tools:
rustc 1.100.0, cargo-llvm-cov 0.8.7, project syn 2.0.119 frontend. Scoped LCOV,
per-function counters and source hash are retained. Only the exact common test
object reported by Cargo was exported; profiles remain in `/tmp/blent-t1417-profiles`.
