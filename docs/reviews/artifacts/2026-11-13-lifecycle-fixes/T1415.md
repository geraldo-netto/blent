# T1415: recover capture after failed pause control

Supervisor-owned pause recovery now treats failed control as a requirement to
retire the original helper. It terminates that child and waits for its exact child
and stdout completion before returning. The strict direct `quiesce_display`
boundary and its original invalid/unavailable-control regressions remain intact.
That boundary waits for the encoder generation before returning a control/FIFO
error. The generation retains original reader, idle-controller and native
completion receipts, independently of the encoder child. Recovery therefore
cannot publish a pause receipt while those owners are outstanding. The capture
supervisor remains available, and the
existing desired-work gate permits a fresh helper/codec/IDR only after demand
resumes. Successful pause still retains its original monitor/helper.

Ownership remains in `HelperProcess`, `EncoderProcess` and the original session
retirement recorder. No new allocation pool, command owner or resource identity
was introduced. The recovery path reuses their existing completion certificates;
it does not replace missing native evidence with a timeout. Cancellation retains
original completion fields, and the next pause/replacement attempt waits for the
same debt. Eventual recovery assumes the original native child/stdout/encoder
owners eventually settle. Permanent blocked-cleanup fixtures check the safety
boundary independently from that eventual-progress assumption.

Permanent tests in `host/src/capture/pause_recovery_tests.rs` cover invalid pause
ACK, control EOF, retained original helper cleanup before quiescence, cancellation
followed by retry, a cancelled reader generation still executing native work,
and pause failure while replacing the encoder after a settings change.
They use the existing private helper/FIFO fixtures and native
encoder. A child-owned cleanup lease deliberately blocks its original completion;
release is sponsored by an RAII test guard, including assertion unwinding. No
live EVDI device, tablet, service, or configuration is modified.

The three initial regression cases were added before the behavior change.
`T1415-red.log` records all three failing with explicit supervisor-termination or
premature-return assertions. Cancellation, reader-generation and encoder-replacement
cases were added afterward. `T1415-coverage.log` records the final cases and
strict existing pause/reader/quiescence regressions under the final implementation.

Per-function measurements and the wider affected-suite run are recorded in the
adjacent `T1415-metrics.json`, `T1415-complexity.json` and `T1415-coverage.log`.
All 40 selected tests passed: 25 activity tests, 4 quiescence tests, 7 unchanged
strict pause tests and 4 reader/idle-retirement tests. The three changed production
methods measure 100%, 100% and 92.31% executable-line coverage individually, with
cyclomatic complexities 4, 1 and 7. All 17 measured new/changed methods, including
test helpers, are <=9. The original three red-before-green regressions and three
additional boundary cases remain in the normal automated suite.

Native LLVM counters used Rust 1.100.0 and cargo-llvm-cov 0.8.7. Final profiles
were isolated in `/tmp/blent-t1415-final2-profraw`; LCOV export used exactly the
binary test object reported by the four Cargo test commands. Earlier exploratory
profile directories were excluded. Complexity used the locked syn 2.0.119
frontend. Metric JSON records source hashes and exact missing lines.

These private process/adapter fixtures do not establish physical suspend/resume
acceptance or unrestricted native lifetime safety.
