# T1416 — fence display workers across Activity replacement

`BlentApplication` now owns one lazy `DisplayWorkerOwner`. Every default
`RemoteDisplay` uses that process-owned coordinator instead of a separate native
retirement lane. The Activity adapter retains presentation and its local
non-repeating generations; the coordinator owns native admission. Existing
`AndroidWorkerRun` and `MediaWorkerService` retirement/authentication contracts are
unchanged. No compatibility path or production reset was added.

The coordinator admits one original native owner and one latest wanted request
through the existing `ResourceLane`. Client operations carry opaque identities.
An old Activity's stop, Surface destruction or queued observation cannot clear a
new client's request. Superseded receipts check both local generation and current
client ownership. Constructing or configuring an unstarted view does not acquire a native worker;
only an admitted wanted display with valid routes/Surface reaches its lazy factory.

## Permanent regressions and verification

Before production edits, the first three methods in `DisplayReplacementTest`
failed **6/6 API 27/34 executions**: replacement bypassed held native retirement,
more than the latest wanted request acquired workers, and a withdrawn pending
replacement had already acquired one. `T1416-red.log` and `T1416-red.xml` preserve
those failures. Those unchanged regression bodies pass after the fix. Additional
permanent cases cover live-client supersession, stale receipts and Surface
callbacks, canceled sponsors, unopened factories, factory failure and failed
native retirement.

`DisplayReplacementNativeTest` runs actual `RemoteDisplay`, `AndroidWorkerRun`
and `MediaWorkerService` code against a hosted cached-Binder/death boundary. Its
**2/2 API 27/34 executions** verify: original native retirement blocks replacement;
local native completion alone still cannot admit another bind; original Binder
death and unbind permit one successful fresh-Binder replacement; old Activity
cleanup cannot stop that successor. It shares one explicitly injected coordinator
with an Unconfined dispatcher for deterministic scheduling. Separate
`DisplayReplacementTest` cases exercise default application-owned sharing.

Final instrumented verification: **124/124 executions passed across 11 suites,
zero skips**. JaCoCo 0.8.15 records **100% executable-line coverage for all 60
line-bearing method/callback variants** in `DisplayWorkerOwner`,
`DisplayWorkerRequest`, `RemoteDisplay`, `BlentApplication` and their compiled
callbacks. Both retained RemoteDisplay constructor variants pass. Exact scoped
counters are retained in `T1416-method-coverage.xml`; `T1416-metrics.json` records
the suite results, descriptors and source hashes. This is not whole-project
coverage or physical device acceptance.

The project Kotlin PSI 1.9.20 cyclomatic checker measured **259 authored owners
across the 3 production and 5 test/fixture files**; maximum **6**, none above 9.
Scores and hashes are in `T1416-complexity.json`. `T1416-green.log` and
`T1416-coverage.log` contain the final successful run. The normal test suite retains
all new regressions; no probe is substituted for permanent coverage.

## Ownership, cleanup and bounds

- **Sponsor/admission:** the Application owns the coordinator and scope. One
  ResourceLane owns the actual run through execute completion and successful
  retirement; one pending request stores only the latest desired factory.
- **Handoff:** a factory is exchanged out of its request before invocation.
  It creates an inert LifecycleRun wrapper. Native work still begins in execute;
  the original Android worker retains its own Binder, native control calls and
  borrowed Surface through its existing retirement protocol.
- **Cutoff:** client replacement/clear detaches old event/completion/status
  callbacks and clears any unopened factory immediately. The retained native
  run's event relay then points to a detached request, not a destroyed Activity.
  The metadata status callback captures its StateFlow rather than the Activity
  adapter. A callback already borrowed before cutoff must also pass current
  generation/client checks before publishing.
- **Settlement/reuse:** canceled or superseded pending factories never acquire
  native work. A proven NOT_STARTED outcome settles unopened callbacks even when
  the sponsoring scope was canceled. A started worker's replacement waits for
  original execution completion plus AndroidWorkerRun retirement, including
  actual Binder-death evidence, original control-call completion and unbind.
- **Failure:** unknown native retirement keeps the original run quarantined in
  ResourceLane's RetirementGuard and closes further admission. New clients cannot
  erase that obligation. This bounded retained ownership is not declared a leak
  fix or automatic recovery; no timeout is treated as successful release.
- **Fixture cleanup:** permanent fixtures stop their original receivers, release
  held retirement barriers, join owned scopes, and release both Surface and its
  separately owned SurfaceTexture. The native-boundary fixture joins each hosted
  service scope, including unopened service slots, before releasing output.

Eventual cleanup is conditional on the original native operations and scheduler
providing their required completion/death evidence. The tests exercise finite
interleavings and simulated failures; they do not prove unrestricted scheduling,
physical memory erasure or native driver/process behavior.

## Hosted limits and fixture diagnosis

No physical Android app, device setting, USB connection or display was changed.
The Binder fixture models death and caches the first service Binder as Android's
[bound-service contract](https://developer.android.com/develop/background-work/services/bound-services#the-basics)
specifies. Its injected EXIT grace is 60000 ms so the test controls the earlier
proof boundary without racing the production 500 ms grace. It releases its gates
immediately during cleanup; elapsed time is not the test oracle.

Two exploratory hosted runs were stopped after a scheduler stall was diagnosed:
`runBlocking` occupied Robolectric's main thread while the new process owner used
that unpumped Main dispatcher. One duplicate Gradle run was also started during
inspection; both owned test JVMs were stopped before the sequential rerun. No
physical Binder/native process existed in those JVMs. The final fixture uses one
shared injected scheduler, preconstructs services on the test thread and joins
every fixture service scope. Those incomplete runs are not reported as passes.
The initial completed 48-case cohort had one fixture assertion incorrectly
requiring exactly one cleanup diagnostic; ResourceLane emits the same failure at
multiple lifecycle stages. The retained assertion requires nonempty diagnostics
that all preserve unconfirmed retirement, plus closed admission and detached
observers. `T1416-initial-cohort.log` preserves that initial result.

## Reproduce final verification

From the repository root with the existing dependency cache:

```sh
JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64 \
ANDROID_HOME=/backups/disk1/apps/android-sdk \
./android/gradlew -p android --offline -I ../scripts/coverage/android.init.gradle \
  :app:testDebugUnitTest \
  --tests com.blent.DisplayWorkerOwnerTest \
  --tests com.blent.DisplayReplacementTest \
  --tests com.blent.DisplayReplacementNativeTest \
  --tests com.blent.RemoteDisplayTest \
  --tests com.blent.RemoteAdaptersTest \
  --tests com.blent.DisplayActivityLifecycleTest \
  --tests com.blent.JoinedDisplayActivityTest \
  --tests com.blent.AndroidWorkerRunTest \
  --tests com.blent.MediaWorkerServiceTest \
  --tests com.blent.ResourceLaneTest \
  --tests com.blent.RetainedAdbCutoffTest \
  :app:profileCoverage
```

The red command was the ordinary `:app:testDebugUnitTest` task filtered to
`com.blent.DisplayReplacementTest`, before production changes and before adding
the fourth control method.
