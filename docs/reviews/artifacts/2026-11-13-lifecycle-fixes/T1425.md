# T1425 — private runtime for route fixtures

The route tests inherited the live runtime directory, so their simulated USB
identity and endpoints competed for the native display-route lease with an
unrelated owner. `T1425-lock-trace.log` records `flock(LOCK_EX|LOCK_NB) = EAGAIN`;
`T1425-route-isolated-runtime.log` records the same unmodified test passing with
only a private runtime directory. The detached baseline failed identically.
Empty USB `getprop` output is a supported fallback, and fake shell exit success
satisfies the current token-delivery contract; neither was the cause.

`host/src/monitor/route_tests.rs` now runs each original route case in its own
0700 temporary runtime and configuration directory. The parent retains that
directory until the original child exits. The permanent T1425 regression holds
a real public `NativeCommands::display_route_lease` in an owned private parent
namespace, then runs an original route case. It checks that the case chooses an
independent namespace; it does not duplicate the lock hash or touch live leases.
Two T705 cases now mutate only externally owned mappings, preserving their
foreign/unrelated mapping assertions and the exclusive endpoint contract.
Those two cases finish cleanup before their readiness assertions. Passing
fixtures settle their original work before deleting their private directories.

Validation:

- `T1425-red.log`: the permanent regression failed with the original inherited
  namespace behavior, before enabling the isolation helper.
- `T1425-green.log`: all 9 route tests passed (8 original cases plus the new
  regression). Invocation: current `blent` binary test executable with
  `monitor::route_tests:: --nocapture --test-threads=1`.
- `T1425-complexity.json`: all 12 changed/new functions measured with the Blent
  syn 2.0.119 frontend; maximum cyclomatic complexity 8. Source SHA-256 is retained.
- `T1425-callers.log`: all 57 selected monitor, discovery, daemon-activity and
  capture caller tests passed. Initial filters matching zero tests were rerun
  against the actual module/target. The additional library resource test passed
  its one-session trial, then failed its next control handshake with connection
  reset. That separate fixture issue is tracked as T1426; no resource assertion
  was weakened and no passing result is claimed for that test.

This change affects test fixtures only, so no changed production function needs
new coverage measurement. Validation used loopback and fake ADB processes with
private runtime/configuration paths. No physical device, live service, driver,
or suspend operation was changed. Owned stalled probe processes were reaped;
there is no evidence that the unrelated live lock owner represented fixture debt.
Profiles and executable build artifacts remain outside the tracked artifact set.
`T1422.md` and `T1425-reproduction.json` correct the earlier unsupported cleanup
interpretation.
