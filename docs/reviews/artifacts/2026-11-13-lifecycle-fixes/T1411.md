# T1411 — retain Linux process exit until admitted cleanup settles

The Linux entry now closes admission to session/display-route owners, signals
live supervisors, and drains their original completion observations while Tokio
remains alive. Normal/error returns, caller loss and unwinding cannot skip that
drain. The work result or panic is returned only afterward. The existing bounded
runtime shutdown remains for residual unadmitted work (T819); the independent
Wi-Fi exit fence is preserved. No live service or tablet was modified.

Architecture: reuse the existing bounded resource pools and their exact
`Completion` observations. `process_retirement::Registry` observes those pools;
it does not become a second resource owner or duplicate mutable resource state.
Its mutex serializes reserve/publication with cutoff. `CancellationToken` wakes
active session supervisors and original route workers; their established cleanup
paths still own the effects. The process refuses new session and route admission
after cutoff, including a newly constructed route facade. Normal/error/cancelled
callers can drop their facades without losing original cleanup ownership.

The observation registry has an explicit 8192-proof bound: the combined maximum
of the two supported 4096-owner pools. This independent bound also accounts for
the interval between `Admission::drop` decrementing its pool count and publishing
completion. Admission first removes completed history, then rejects observation
exhaustion before reserving the underlying pool. Capacity rejection starts no
native operation. Empty/repeated drain, capacity exhaustion/recovery and cutoff
are permanently covered. The `Vec` holds only completion observations; original
pool records retain native handles, leases and cleanup sponsors.

Ownership: session admission precedes worker creation; route admission precedes
its original native worker. Shutdown closes future admission, requests owner
retirement, and waits for the existing task/native/thread/TLS settlement proofs.
Only completed proofs leave the registry, and only then can process teardown
release its runtime. Unknown or failed native outcomes remain owned. Conditional
liveness requires functioning runtime/observer scheduling and eventual original
cleanup success; permanent native failure deliberately prevents graceful exit.
The in-memory fake tests do not claim physical ADB or Windows acceptance.

The existing Linux `blent daemon stopped` message is workflow completion before
`runtime_owner::run` returns, not proof of process exit. Its function was left
unchanged; this patch measures the process ownership/control methods it changes.
T1412 separately handles managed-service forced-stop policy.

## Permanent red/green evidence

- `host/tests/process_exit.rs` is in Cargo's normal integration suite. Its owned
  fake routes retain a lease through rejected-before-start removal; its capture
  backend registers an original native completion whose cleanup must run
  asynchronously on the still-live runtime. The fixture holds both active
  facades, or aborts their caller, and exercises normal/error/cancel/panic exit.
  Each scenario verifies no early return, actual cleanup, original proofs,
  correct return/panic propagation and rejection of session/new-route admission
  after cutoff. No native input, real mapping or service operation occurs.
- `T1411-red.log` records the initial failing regression before production edits.
  `T1411-final-red.log` records the final permanent fixture copied unchanged to
  an isolated pre-fix `56250b92` checkout: 4/4 exit modes fail on premature entry
  return. That owned temporary worktree was removed after preserving evidence.
- `T1411-green.log`: process-exit 2/2, bounded runtime-exit 2/2 and Wi-Fi-exit 2/2
  tests pass. The new process-exit test includes four child scenarios.
- `T1411-coverage.log`: final instrumented sources pass 89/89 selected tests:
  registry 3, session-supervision 5, USB 58, process-exit 2, runtime-exit 2,
  Wi-Fi-exit 2, session-failure 16 and shutdown-deadline 1. These are selected
  cohorts, not a whole-repository suite claim.
- `T1411-metrics.json`: 10/10 changed production functions meet >=80% executable
  line coverage; eight are 100%, session `reserve` is 26/27 (96.30%), route
  `reserve` is 11/12 (91.67%). The uncovered lines are error conversions from
  failed static pool initialization; they remain in the denominator.
- `T1411-complexity.json`: all 81 functions measured in the scoped production
