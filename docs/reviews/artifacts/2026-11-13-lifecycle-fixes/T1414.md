# T1414 — retain ADB delivery cutoff across Activity replacement

The authoritative USB-selection cutoff now lives beside the persisted protected
ADB delivery counter in `Prefs`. Each external selection records the current
counter. A new `SessionCoordinator` reads that authority and clears its default
control/video routes before startup when no later protected delivery exists.
The old Activity-local counter copy is removed. A later protected delivery still
restores ADB, while an untouched installation retains its token-delivery startup
handshake. Invalid or exhausted cutoff values fail closed.

`RetainedAdbCutoffTest` is a permanent normal-suite regression. Before production
changes, its 12 API 27/34 executions produced 8 assertion failures: disconnect,
denial and revocation followed by actual Activity create/start replacement, plus
new coordinator composition with empty process-owned USB state. The four
untouched/fresh-delivery controls passed. The same regression source passed after
the fix; see `T1414-red.log`, `T1414-red.xml`, and `T1414-green.log`.
`AdbDeliveryCutoffTest` permanently adds 8 API 27/34 executions for boundary
values, cross-instance preference ownership and the untouched startup handshake.

Final verification used Gradle 8.5, Robolectric 4.17 and JaCoCo 0.8.15:
**68 executions across 7 suites, zero failures or skips**. All 6 changed native
method variants have **100% executable-line coverage**, including both retained
constructor variants. `T1414-method-coverage.xml` preserves their exact counters;
`T1414-metrics.json` records method descriptors, suite results and final source
hashes. The scoped Kotlin PSI 1.9.20 complexity checker measured all 150 authored
owners in the 2 production and 2 test files; maximum **8**, none above 9. Results
are in `T1414-complexity.json`. No full-project coverage claim is made.

## Ownership and persistence scope

The existing main-process SharedPreferences file owns one additional bounded
64-bit cutoff; no worker, Context reference, callback or native resource is added.
Cutoff writes and protected delivery writes use the same existing `deliveryGate`.
The coordinator owns only its current external-route state and existing token
observation until `stop`; replacement reads the stored authority rather than
reconstructing permission from its launch Intent or inactive USB presentation.
No alias, migration or compatibility fallback is introduced: absence of a cutoff
is the actual untouched-startup state.

Normal Android SharedPreferences persistence is retained, including its existing
asynchronous `apply` behavior. The hosted tests construct replacement preference
and session owners; they do not kill a real Android process or establish durable
writes across arbitrary crash/power-loss during an in-flight storage operation.
No physical device was stopped, restarted, reconfigured or otherwise exercised.
All test Activity controllers, socket fixtures, workers and media owners are
settled by their existing cleanup paths. Native display-worker replacement
retirement is a separate finding, T1416.

## Reproduce final instrumented verification

From the repository root with the populated local dependency cache:

```sh
JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64 \
ANDROID_HOME=/backups/disk1/apps/android-sdk \
./android/gradlew -p android --offline -I ../scripts/coverage/android.init.gradle \
  :app:testDebugUnitTest \
  --tests com.blent.RetainedAdbCutoffTest \
  --tests com.blent.AdbDeliveryCutoffTest \
  --tests com.blent.RevokedAdbDeliveryTest \
  --tests com.blent.SessionDisplayRouteTest \
  --tests com.blent.SessionRevocationTest \
  --tests com.blent.TokenDeliveryTest \
  --tests com.blent.connection.AttachmentRecreationTest \
  :app:profileCoverage
```

The red command was the ordinary `:app:testDebugUnitTest` task filtered only to
`com.blent.RetainedAdbCutoffTest`, executed before production edits. Logs retain
that expected failing result. The first green log covers the 50-execution cohort;
`T1414-coverage.log` is the final 68-execution instrumented cohort.
