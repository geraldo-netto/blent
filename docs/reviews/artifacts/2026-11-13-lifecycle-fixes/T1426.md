# T1426 — resource replay input identities and native settlement

The replay constructed every control server with default input instance 0. After
T1422, the real Linux adapter rejects concurrent claims of that identity until
its original native lifetime settles. `T1426-rejection.log` records a debugger
breakpoint at the error return in `Identity::claim` with `instance=0`, following
a successful one-session trial. The stack continues through `Lifetime::claim`,
`Backend::follow`, `InputServer::run_with_listener`, and the replay's `control`.
The subsequent client handshake fails with connection reset. This is a fixture
contradiction, not a reason to weaken production identity ownership.

The fixture now passes distinct bounded trial indices through session and control
construction. Each Control retains the exact native completion captured before
server startup. Its finish method aborts and joins the server, then observes that
original completion before returning. Thus fd/task sampling and subsequent trial
identity reuse follow original native settlement. Existing socket, task, frame,
codec-transition, and retained-byte assertions are unchanged. The completion wait
has a five-second test observation bound; timeout fails the test and never marks
an unknown native obligation complete.

Permanent regression `t1426_concurrent_controls_settle_original_native_lifetimes`
was added before changing fixture behavior. It executes two consecutive trials
of two concurrent sessions, retaining all existing trial assertions. The existing
T391 one/two/four-session replay remains in the normal suite.

Validation:

- `T1426-red.log`: the new regression fails before the fixture correction with
  connection reset at control handshake.
- `T1426-green.log`: both replay tests pass, including two consecutive two-session
  trials and the existing one/two/four-session replay. For the latter, each trial
  starts and ends at 10 file descriptors and 0 live Tokio tasks; all 7 readers
  receive 120 frames and 2 codec configurations. These are fixture measurements,
  not hardware or performance support claims.
- `T1426-complexity.json`: all 8 changed/new test functions measured with the
  Blent syn 2.0.119 frontend; maximum cyclomatic complexity 3. The measured source
  SHA-256 is retained. No production function changed.

Build: `cargo test -p blent --features accessory-transport --lib --no-run
--message-format=json`. Run the resulting library test executable with
`stream::resources:: --nocapture --test-threads=1`. Each run used a fresh 0700
runtime/configuration directory, a nonexistent private session-bus address, and
no DISPLAY or WAYLAND_DISPLAY. The existing replay helper launches isolated child
processes and waits for their exit. Profiles and binaries remain external.

For the rejection trace, run that same library executable under GDB with
`BLENT_T391_REPLAY_CHILD=1`, break at `host/src/input/linux/lifetime.rs:25`, print
`instance`, capture `bt 6`, then continue the exact T391 replay. The breakpoint is
on the failed identity insertion branch. No source instrumentation was used.

No live service, physical input device, display, suspend, or driver action was
performed. Touch, pen, and pointer construction remain disabled by this fixture.
The observed task counter is Tokio's live-task counter, not the process thread
count; no new thread baseline exception or resource assertion adjustment was made.
