# T1423 — retain shutdown signals throughout daemon startup

The Linux daemon now owns SIGTERM and SIGINT observation before configuration
loading or resource admission. One independent Tokio observer latches the stop
and closes the existing process admission registry immediately. Initialization
keeps its original owner/future; it is not cancelled to implement stop. The
post-validation checkpoint rejects pre-admission startup before PID/runtime
publication. Later session, route, activity and input admissions use the same
atomic cutoff as before.

Only a requested stop's typed `AdmissionClosed` rejection becomes successful
shutdown. Configuration validation and unrelated I/O errors retain their error
results. The existing late-only signal registration was removed; tray requests
and remembered signals enter the normal shutdown workflow. Registry retirement
continues to retain the executor until original proofs settle.

## Permanent red/green evidence

`host/tests/daemon_startup.rs` runs the actual Cargo-built daemon using:

```
/usr/bin/unshare --user --map-root-user --mount --pid --fork --mount-proc \
  /usr/bin/python3 host/tests/daemon_startup/signals.py <Cargo blent executable>
```

The namespace controller mounts private tmpfs over `/dev`, uses an owned HOME,
configuration/runtime directory, fake-only ADB PATH, invalid D-Bus endpoints,
relative invalid broker state, `/bin/true` capture helper and disabled inputs.
No real daemon, service, ADB server or device is controlled. Temporary files and
pipe descriptors are owned per case. The direct child is reaped on success and
failure; PID-namespace teardown is the final descendant containment boundary on
controller failure, rather than a claim that direct-child reap fences descendants.

The regression was added before production edits. `T1423-red.log` records the
first blocked-banner case: SIGTERM handler absent, exit **-15**, **2** fake routes
remaining. The same permanent assertion now passes. The fixture was subsequently
strengthened with an explicit banner observation for the post-startup control and

## Ownership and limits

The Linux listener owns exactly one watch state, two signal streams and one
original task. Its task owns both streams until observation or cancellation;
Drop aborts that original task on startup error, normal return or owner loss.
Tokio releases those stream/task allocations when abortion is observed. The
process-global signal dispatcher remains Tokio-owned; this change does not
claim to restore the OS default disposition after stream drop. There are no
native device leases in the listener and no retained task cycle or borrowed view
escaping its owner.

Publishing the remembered reason precedes synchronous admission cutoff, so a
cutoff rejection cannot outrun its stop classification. Returning from `wait`
also performs idempotent cutoff. New admission and cutoff share the existing
registry mutex. Previously admitted work may still finish creation and cleanup;
its original proof remains funded and no deadline permits release or reuse.
The T1422 registry grant of 12292 observations is unchanged by this fix.

Conditional exit still requires original owners and cleanup to make progress.
The fixture does not prove arbitrary blocking startup I/O becomes interruptible,
GPU/native safety, or hardware/device behavior. It verifies real signal dispatch,
startup ordering, private ADB route cleanup and error reporting under the stated
bounded fixtures. SIGKILL and other uncatchable termination remain outside the
graceful shutdown contract. No new finding remains only in this evidence.
