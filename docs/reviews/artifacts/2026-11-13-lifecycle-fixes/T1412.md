# T1412 — service termination ownership

Both shipped templates now request `KillMode=mixed`, `SendSIGKILL=no` and
`TimeoutStopSec=infinity`. The service manager signals only the parent daemon;
the daemon owns native child cancellation and exact retirement. Removed the
redundant ExecStop CLI and renderer branch. The CLI/GUI response deadlines
remain unchanged; a timed-out client does not cancel the manager's pending job.
Development documentation describes that distinction and forced-exit limits.

Permanent regression: `scripts/tests/test_service_retirement.py`, discovered
by the existing Python script suite. Before the fix, both template checks and
both native stop cases failed: after 16 seconds each original process had been
killed and its unit was failed. After the fix, all three test methods pass:
both native stop cases retain the original owner past the former 15-second
timeout, and restart cannot launch the replacement before original settlement.
The child receives no service-manager SIGTERM. The owner releases its child,
waits for its exit and publishes settlement before returning. The restart case
then observes a fresh invocation. Logs retain the red and green results.

Each native case owns a uniquely named transient `blent-t1412-*` unit and a
private temporary directory. On assertion failure it releases the gate and
settles/stops that exact unit before directory removal. A naturally completed
and garbage-collected transient unit is accepted only with the settlement
marker. The final native-unit inventory is empty. No installed Blent unit,
daemon, tablet or user configuration was modified.

Validation:
