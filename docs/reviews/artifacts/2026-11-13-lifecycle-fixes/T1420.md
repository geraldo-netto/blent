# T1420 — propagate null display cutoff by original transition identity

The connection reducer now publishes an opaque identity with every actual display
selection/cutoff transition, after recording the T1419 authority cutoff. An
untouched connection has no identity. Metadata, repeated values and original
worker retirement preserve the current identity. The Activity adapter applies
each identity once, independently of whether its admitted endpoint is null. It
no longer retains a nullable display choice as its deduplication authority.

This closes the sequence: USB opening selects no route; protected delivery later
admits ADB; disconnect, denial or revocation still selects no USB route but must
retire the previously admitted control/video route. A subsequent protected
delivery can restore ADB. Retirement of the original connection does not cut off
that newer delivery or replace its control socket.

## Permanent regression and measured evidence

`NullDisplayCutoffTest` contains three actual hosted MainActivity / ConnectionBinding /
SessionCoordinator composition regressions, each on API 27 and 34. All 6 executions
failed before edits at the retained-control-route assertion (`T1420-red.log` and
`.xml`). The same assertions now pass, including control socket cancellation,
cleared control/video routes, subsequent fresh delivery and held original-retirement
controls. No native video execution is claimed: these cases supply no Surface.

`ConnectionCutoffTest` verifies the source identity changes for a null-route stop,
survives metadata/retirement, and changes again for a new attempt.
`ConnectionDisplayBindingTest` now constructs explicit source identities; it
retains its unchanged-snapshot, exact-credential, invalid/foreign-snapshot and
untouched-startup assertions. The production reducer is the sole identity issuer;
these synthetic values are independent adapter contract inputs.

## Lifetime audit and limits

ConnectionPresentation remains the process-owned transition authority. Each real
transition allocates one empty identity object; its current StateFlow snapshot
and Activity projection may borrow it. No wrapping counters, history or queue is
introduced. Snapshot replacement releases the previous reference once existing
observers finish; identity holds no credentials, Activity, Surface or native
resource. Adapter replacement discards its last identity and projects the current
source state; T1419 handles already ordered delivery independently of UI lifetime.

One Activity-owned adapter holds its target and one opaque identity, replacing
its previous choice-plus-claimed cache. It runs only on the main thread. Its
normal StateFlow consumer observes serialized source transitions; it does not
invent transitions or replay cutoff writes. Native cleanup remains sponsored by
the existing display and connection owners, including unknown-retirement quarantine.
The new fixture destroys the Activity, cancels/joins its control scope, resets
media fixtures and settles every held connection worker through fixture cleanup.

Evidence is hosted/source-only. No physical tablet, app installation, settings,
USB attachment or running tablet session was changed. This fixes route admission
and revocation; it makes no host authentication/TLS bypass claim or new platform
support claim.
