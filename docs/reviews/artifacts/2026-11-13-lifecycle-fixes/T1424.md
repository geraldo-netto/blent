# T1424 — align reattach regression with observed attachment epochs

The retained T1392 test expected a second worker after two copies of the same
attach Intent. T1396 intentionally requires an observed new native attachment
epoch; duplicate delivery cannot mint one. Unmodified commit 9f8660aa reproduced
the contradictory expectation on both API 27 and API 34 (the T1419 baseline
artifacts), and `T1424-red.log`/`.xml` record the same 2/2 failures immediately
before this correction.

`ConnectionReattachTest.t1392AttachmentDuringOldExecutionSurvivesUntilRetirement`
now uses NativeAttachmentFixture to publish an observed detach followed by the
supported accessory snapshot before delivering the new attach Intent. It retains
all original assertions: one worker while original execution is held, no
cancellation of the original, and exactly one replacement after retirement. The
additional duplicate Intent while that new request is pending remains in the test.

`t1424DuplicateAttachmentCannotMintAReplacementEpoch` preserves the original
same-epoch input as an explicit negative control: repeated Intents do not cancel
the worker or admit a second worker after its completion. Main-loop work is drained
before asserting absence. Both tests are permanent normal-suite tests. Their four
API-specific executions pass (`T1424-green.log`). No production code changed.

The original broad Android cohort is also rerun with the new T1420 regressions;
its final case counts, native counters and current source hashes are recorded in
`T1424-integrated-metrics.json` and `T1424-integrated.log`. Scoped Kotlin PSI 1.9.20
measurement gives all four retained test functions/lambdas complexity 1
(`T1424-complexity.json`). Production function coverage is not newly required by
this test-only correction; the integrated counters verify the previous two fixes.
The integrated run passes 692/692 cases in 102 suites, with no skips. All 17
maintained native method variants from T1419/T1420 remain at 100% line coverage.
