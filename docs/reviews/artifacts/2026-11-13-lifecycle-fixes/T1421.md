# T1421 — activity-source process-exit fence

`Following::start` now obtains its original source admission through the existing
process registry. The source pool and `SourceLifetime` remain authoritative for
actual task/native ownership; the process registry observes their exact original
completion. Dropping or cancelling the facade still stops/aborts its existing
follower, and its retained cleanup/native owners must settle before process exit.
No native implementation, activity policy, recovery algorithm, runtime owner or
Linux main workflow was rewritten.

The process observation grant increases from 8192 to 8196 for the supported four
activity sources. The independent bound still covers completion-publication gaps
in underlying pools. Its permanent capacity test funds two 4096-owner pools plus
a four-owner source pool, rejects a further observation before creating work,
then verifies reuse after original settlement. Post-exit source creation is also
rejected. Session/route and Wi-Fi exit behavior remains independently covered.

Ownership audit: source admission precedes task/native creation; `SourceLifetime`
registers original native proofs before exposure. Normal shutdown, timeout,
failed or cancelled creation, caller loss and unwind drop the facade while the
pool sponsors original task/native settlement. The new registry observation
outlives that facade and keeps the runtime available. No observer substitutes
logical stop, a deadline, or a refcount for native completion. Eventual exit
requires original work/cleanup to finish and its proof to become observable;
permanently unknown native work intentionally retains admission. No installed
service, native device or tablet setting was changed.
