# T1419 — order protected delivery at the original connection transition

The process-owned connection reducer now invokes an injected cutoff port before
publishing a real change of attempt, active state, reconnect eligibility or display
selection. `ConnectionOwner` binds that port to the existing application preferences
cutoff. The reducer remains independent of Android storage. Metadata, repeated
snapshots, stale attempts and retirement-only updates do not advance authority.

`SessionCoordinator.selectDisplay` projects this already ordered state. It never
writes a cutoff during Activity replay. A null projection reconciles any protected
ADB delivery accepted after the original cutoff, including delivery that preceded
a delayed foreground observation. A currently available USB display still takes
precedence. Direct coordinator test fixtures now explicitly represent the source
transition before projecting it; their original freshness assertions remain.

## Ownership and limits

The existing process-owned reducer is the single transition authority. Its
synchronized methods serialize admission and cutoff before StateFlow publication.
The injected callback retains one Prefs object containing application preferences;
it captures no Activity, surface, worker or listener. Prefs' existing delivery gate
orders accepted deliveries against the one persisted cutoff counter. No new queue,
resource slot, wrapping identity, cleanup sponsor or compatibility path is added.

UI state observation is a borrow of this authority. Stopping/recreating an Activity
cannot manufacture a transition. Explicit source cutoff prevents reuse of an old
delivery; a later protected delivery is a new admission. Existing ResourceLane and
display worker owners still retain native execution/retirement obligations through
failure and cancellation. Their quarantine and original cleanup fences are unchanged.
The new hosted fixture closes its control coroutine scope, Activity and media
owners; connection workers and their scope are settled by ConnectionUiFixture.

This is source review, hosted Robolectric execution and JaCoCo evidence. It does
not exercise tablet process death, actual USB transport or physical Android native
resources. No device, package, settings or tablet session was changed. T1420's
nullable-selection deduplication remains a separate route-revocation fix.
