# T1418 — retain known activity capabilities across native recovery

Linux `Factory` and `PowerFactory` now own bounded capability-admission history.
Each independently created factory starts with no admitted capabilities. A
successful source can add capabilities; later candidates cannot silently remove
them. Missing known power, lock or display observation rejects that candidate,
so the existing follower publishes conservative failure and retries after the
original attempt's complete native settlement and configured backoff. A first
source with genuinely unsupported backends still succeeds explicitly.

The shared follower contract still permits legitimate fresh capability changes
from other implementations. The additional continuity policy belongs to the
Linux adapters. Current callers construct their own default factory; no obsolete
unit-constructor compatibility path is retained.

## Ownership and boundaries

Continuity stores exactly three capability booleans behind one shared mutex.
It stores no observations, epochs, source handles or native completion owners.
The factory owns this history; an admitted creation borrows it through an Arc
clone. There is no cycle or growing production collection. The history lives
until the factory and its in-flight creations are dropped.

On candidate rejection, ordinary `LinuxSource` destruction requests stop for
its exact original actors. Their existing source-lifetime and task sponsors
retain native cleanup independently of that source handle. The follower retains
the attempt receipt and cannot retry before it settles. Explicit stop revokes
future attempts while the original completion still governs retirement. No
replacement inherits old observations or native identities. Initial creation
errors and invalid settings still follow the existing ownership path.

Tests establish these finite adapter/follower transitions and held-receipt
boundaries. No physical suspend/resume, USB, EVDI, live daemon, tablet or system
configuration operation was performed. Conditional eventual recovery still
requires a valid owner to return and native cleanup to finish.
